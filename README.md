# 1. はじめに

本文書は、AIを用いた文書フィードバック機能を持つブラウザ拡張機能 *AutoReviewer for Browser* ver2の要件定義書である。

ver1ではAutoReviewer for Browserをペルソナ(架空読者)に基づいたAI文書レビューアプリとして定義した。

ver2ではペルソナ機能を削除し、文書の誤字・脱字の自動指摘に特化したアプリとして開発を行う。さらに、LLM(ここではGPT-baseの大規模言語モデルを指す)以外の自然言語処理技術をバックエンドに導入し、高精度の誤字・脱字検出を目指す。

## 1-1. なぜ ペルソナ機能 を外すのか

- テストで 複数ペルソナ（教授・学生 etc.）を設定しても、
誤字・脱字 が存在する場合は 誰の視点でも同じ指摘 になる。
- ペルソナ毎に出力差がほとんどなく、設定フローが UX の障壁になる。
- 確実な間違いである誤字・脱字に比べて指摘事項が的外れになることが多い。

## 1-2. LLM 単体の限界

LLM単体での誤り判定の問題点として、コスト面での問題と長文の取り扱いがある。

| 課題 | 影響 |
| --- | --- |
| **長文（数万字）を丸ごと投入**すると context 上限を超えるため、回答の精度が極端に悪くなる。 | チャンク分割が必要／指示文重複でコストが増える。 |
| **入力トークン量＝従量課金** | 100 k token で数百円〜千円／回 |
| **誤字脱字検出はルールで十分拾える** 部分が多い | LLMの指摘が誤字脱字に偏っている場合は無駄が多い。 |

**結論**：

1. 軽量 OSS NLP で 8〜9割は自動検出する。
2. LLM は「曖昧ケースの最終判断」だけを行うように設定する。

誤り判定タスクにおいては、Encoderをベースにした言語モデルBERTがLLM(GPT-4)の精度を上回るという調査もあり、複合モデルの有用性を示唆しているが、LLM単体での誤り判定との比較には検証を要する。
